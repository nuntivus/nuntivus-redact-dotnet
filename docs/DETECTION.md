# Detection, policy, and strategy semantics

Optional [offline NLP](nlp.md) adds replaceable entity providers and a local cased WordPiece/BIO ONNX implementation. Models are provisioned separately; regex/dictionaries remain complementary. Named entities are not necessarily sensitive data, and no trained-model accuracy or all-language coverage is asserted. Category mappings, token/window budgets, model licensing and the existing overlap-coverage tradeoff are documented in that guide.

`PersonalDataDetectors.CreateDefault()` supplies email, phone, IPv4, IPv6, IBAN, HTTP(S) URL and card candidate detectors. Regexes have a 100 ms timeout, 1,000,000 input-code-unit limit, and 1,000 candidate limit per detector. Custom RegexDetector permits a timeout up to one second and patterns up to 4096 characters. DictionaryDetector copies up to 1000 keywords of at most 256 code units, uses ordinal-ignore-case matching, and can enforce letter/digit/underscore boundaries. A one-element dictionary is the custom keyword detector.

These are heuristics, not exhaustive PII discovery. Email handles common ASCII syntax, not the full RFC or IDN space. Phone uses 7–15 digit runs, not national numbering plans, and may match unrelated numbers. IPv6 zone IDs are unsupported. IBAN accepts contiguous syntax and mod97, not country-specific lengths/account rules. Cards use 13–19 digits and Luhn, not issuer validation. URLs may include trailing punctuation. Split, encoded, obfuscated, or context-dependent values may be missed. Confidence is a heuristic score, not calibrated probability.

Core uses original UTF-16 offsets. Policy filters (confidence, inclusion, exclusion, custom predicates) run before overlap resolution. Higher priority wins, then higher confidence, longer span, lower starting offset, ordinal detector ID, ordinal category. Duplicated registrations are rejected. Touching spans do not overlap. Overlapping matches can leave portions of a lower-ranked match untouched: applications must choose priorities to meet their risk model. Strict errors abort the operation. Non-strict/incomplete-result mode is intentionally unavailable.

Policy builders copy configuration on Build; callbacks and extensions must themselves be thread safe. Strategies can be selected per category. Register detectors and strategies explicitly; no reflection plugin loading. Detections carry no matched source values. Context, input, and output still contain sensitive data and must never be logged.

Fixed/category replacements remove accepted matches from returned text, not from caller memory or original files. FullMaskingStrategy reveals grapheme count. PartialMaskingStrategy intentionally retains configured graphemes and fully masks too-short values. HmacPseudonymizationStrategy uses at least 32 key bytes, copies its key, separates categories with a length prefix, and emits full HMAC-SHA256. Outputs remain linkable; protect and rotate keys outside this library. Managed strings cannot be reliably erased; no memory-erasure guarantee is made. Custom strategies may deliberately retain source and are trusted application code.
