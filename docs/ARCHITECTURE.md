# Architecture

## Optional offline NLP boundary

Nlp.Abstractions depends only on Abstractions and defines source-free original-UTF-16 entities and IEntityRecognitionProvider. Detectors.Nlp adapts that contract into ISensitiveDataDetector with immutable category mapping and strict result validation. Nlp.Onnx depends inward on those contracts; MIT ONNX Runtime/Tokenizers remain isolated to that optional module. Core, policies and format processors are unchanged. Explicit constructor/DI registration enables NLP; no discovery, model download or cloud call occurs.

The provider validates hash-verified bounded local assets and an explicit cased WordPiece/BIO tensor profile, processes all tokens through bounded overlapping windows, reconciles token predictions and expands labeled subwords to whole basic words. Source-to-normalized mapping preserves original UTF-16 offsets. Native CPU inference is serialized per provider with bounded active/waiting admission; cancellation requests termination but is not a hard deadline. Caller-owned disposal waits for active work. Only trusted graphs belong in-process; external worker isolation, hard native resource limits and trained multilingual accuracy are not delivered. The existing winner-takes-overlap policy and per-format segment context limits remain explicit. See [NLP](nlp.md) and ADR-012 for exact profiles, failure behavior, licensing and evaluation gates.

Abstractions defines document-independent detection and redaction contracts. Core orchestrates explicitly supplied detectors and strategies with immutable policy. Strategies depend only on Abstractions; detector adapters may also depend on neutral provider contracts or lower-level detectors, never Core. Format packages depend on Abstractions and consume a text-redactor contract; they do not hardcode detectors. Optional DI composes Core and extensions. Optional ASP.NET builds on DI. OCR/NLP contracts are separate from native providers. Samples depend on public packages only.

Text offsets use UTF-16 code units within the supplied text. Detections carry category, span, confidence and detector identity, never source values. Validate ranges before applying edits. Filter by policy before deterministic overlap resolution (priority descending, confidence descending, length descending, start ascending, detector identity ordinal). Transform nonoverlapping spans from original text without rescanning generated replacements. Reports expose counts/locations only, not matched text. Caller-owned streams stay open. Stage bounded output before committing it; output I/O failure still requires callers to discard the destination.

Security boundary: successful text replacement means only accepted detector matches were replaced. It is not proof of anonymization or complete discovery. Structured parsers preserve semantic structure, not original byte formatting. Binary processors are unsupported until their hidden-content and recovery surfaces are verified. No plugin discovery by reflection. No logging of source content. Custom extensions are trusted application code and must follow the same contracts.

Package boundaries mirror the master roadmap. New projects must provide meaningful functionality, not empty shells. PDF/PPTX and native-isolation deferrals remain explicit in TASKS.md and RESUME.md.

## Implemented format and HTTP boundaries

Formats.Csv/Json/Xml depend on Formats.Text for bounded UTF-8 staging and numeric field reporting; Text depends only on Abstractions. Each processor parses/transforms/validates before committing output, rejects nonempty seekable destinations, and leaves streams open. Mixed-content XML, DTDs/PIs, sensitive structural XML identifiers and detected non-string JSON primitives fail closed. JSON original/resulting duplicate keys fail. No byte-for-byte formatting, application schema or signature preservation guarantee exists.

Format syntax is delegated to established libraries: CsvHelper in Formats.Csv only, System.Text.Json for JSON, System.Xml/LINQ to XML for XML, and framework encoding/streams for TXT. CsvHelper is centrally pinned and selected under Apache-2.0; request-local configuration preserves the strict CSV profile, with an explicit EOF quote-balance guard. Format-specific redaction traversal, budgets, cancellation, sanitized failures and staged output validation remain owned by the processors. See ADR-009 and formats/structured.md.

Extensions.DependencyInjection depends on Core and Microsoft.Extensions.Options/DependencyInjection only. It explicitly composes singleton extensions, validates required policy, and preserves Core's standalone path. Host container scope validation is required for captive dependencies. AspNetCore depends on DI/Text and the shared framework; it bounds/stages raw-body requests/responses and returns safe problem codes. Hosts own authentication, TLS, authorization, logging configuration and concurrency controls. The sample disables logging and includes static OpenAPI metadata; no production service or isolated worker is implied.

Supported format profiles and remaining binary package deferrals are in formats/README.md. Separate analyzer/policy/validation contracts remain EXT-001; neutral OCR contracts now exist in Ocr.Abstractions.

## Restricted Office boundary

Formats.Office depends only on Abstractions among product packages, plus MIT DocumentFormat.OpenXml 3.5.1. It implements IDocumentProcessor directly with separate immutable OfficeLimits; BufferedDocumentProcessor remains UTF-8-only. Framework ZIP/XML preflight inventories every part and relationship before SDK loading. Supported nested DOCX/XLSX share aggregate budgets; fresh bounded ZIP output is SDK-validated before commit. No filesystem temporary data, Office automation or native parsing occurs in product code.
Office helpers are instance services behind internal IOfficePackage, IOfficeContent, IExcelContent and IOfficeString interfaces. Public processors explicitly compose these implementations without a DI-container dependency or public constructor changes. Traversal and codecs are reusable; budgets, reports and formula parser state remain request-local. No static Office helper class is used.

IEditAwareTextRedactor is an additive optional capability; ITextRedactor and RedactionResult are unchanged. Core's existing single detection/policy/strategy pass emits ordered original-coordinate RedactionEdit values and final text. Adapters validate edit reconstruction before mapping to runs, preserving unaffected properties and assigning replacement text to the first affected run. Replacement-bearing results are sensitive classes, not source-free reports. DI exposes the same engine under both interfaces; an incompatible custom legacy redactor is never silently replaced. Office registration remains explicit and the HTTP sample does not automatically enable binary formats.

See formats/office.md and ADR-010 for feature rejections, formula/cache semantics, resource defaults and fidelity limits. PPTX, broad Office feature support, PDF, native isolation and binary benchmarks remain deferred.

## Optional OCR and picture boundary

Ocr.Abstractions depends only on Abstractions. Formats.Images and Ocr.Tesseract depend inward on those contracts, never Office or Core. IOcrProvider receives canonical PNG and returns sensitive text with ordered UTF-16 word spans and original-pixel rectangles. RasterImageRedactor validates coverage/geometry/edits, flattens alpha, replaces complete matched words with opaque pixels and encodes metadata-free PNG. SkiaSharp and Tesseract remain isolated to their own optional modules.

Office's additive constructor accepts IImageRedactor; unchanged constructors reject images. OfficeDrawing implements IOfficeDrawing for restricted picture-only DrawingML and alternative text; it does not enable arbitrary shapes/charts/VML. Image parts and nested packages share aggregate image count, decoded pixel and detection budgets. PNG output updates content-type overrides without changing relationship targets. All output remains staged and SDK-validated. In-process native execution is explicitly not sandboxed and cannot guarantee hard cancellation. See formats/ocr.md and ADR-011.
